## つながった実画面での往復

新しい検証セッションの泊の浜から開始し、ノートへ歩いてEで読み、波を再生したまま歩行から泳ぎへ移った。実在するシーン内の船尾はしごへ近づき、Eで乗船。地図の中の浦を選び、到着後にはしごを降り、船体を回り込んで浜に上陸した。

訪問スタンプを受け取り、漂流便を見下ろしてEで回収。船へ泳いで戻って再乗船し、地図で泊へ帰航。下船して調査ボックスまで泳ぎ・歩行で戻り、Eで納品した。荷物は1個から0個へ、記録には`shore-nakanoura`が入り、ポイントは4から7へ変わった。往路・復路の航海記録はそれぞれ約108秒。

この一連の実画面検証には視点ブックマークや座標書き込みを使っていない。視線はブラウザーのdrag、E・J・地図はブラウザー操作、移動は開発用`moveFor`から実際のタッチ移動入力へ送った。キーボードの長押しを実機確認したという意味ではない。プレイ中の状態列と画像は[実行記録](checks/v30/runtime.json)にまとめた。

## 見つかった案内の食い違い

泊で最初の回収を済ませる前に中の浦へ出かけると、目の前の漂流便を調べられるのに、HUDが1km先の泊のシーグラスを指し続けていた。漂流便を1個拾った後も同じ案内が残っていた。

別の浜の近くでは、その浜の未回収の記録を自動で案内する。島の記録を1個回収したら、帰航と拠点への納品を案内する。HUDと調査ノートの「今の目標」は同じ文面を使い、船上・遠い浜・泊の浜・ボックスのそばで必要な行動を示す。自分で指定した目印は優先し、報酬や保存形式は変更していない。

上陸時に実際に獲得した進行記録を、通常保存と別の検証用キーへ入れて同じ状況を再現した。このUI再現だけは検証用の開始座標を使用し、上記の連続往復と区別する。現地の記録→帰還先への切り替わり、調査ノートの一致を実画面で確認。検証用キーの元の内容も完全に復元した。

ブラウザーの最初の確認では開発サーバーが古いmoduleを配信していた。作業ファイルと配信内容を照合して検出し、専用サーバーの再起動後に新しいmoduleとUIを再確認した。ローカルテストだけの成功を、実画面への反映と混同していない。

## 再現できる経路検証

`scripts/verify-island-trips.mjs`は現行のIslandWorld、移動controller、Expeditionを使い、中の浦・新島前浜・羽伏浦・堀切・シークレット・神津島の6地点について、乗船→航海→上陸→再乗船→泊へ帰還→拠点へ戻る処理を実行する。記録のある3地点では回収と納品も確認する。

```sh
node --experimental-strip-types scripts/verify-island-trips.mjs work/island-roundtrips.json
```
