# 海岸・水中・船の検証 V9

実写同等の目標はACTIVEです。生成した軽石の表面と水中の光学改善は独立画像レビューで保持可能と判断されました。白ママの追加崖と巻き波は通常表示へ未採用です。全海岸の現在の実景との一致、全島航海、人間の操作受入は未達です。

## 参照と岩肌

Googleの砂浜写真、航空写真、場所を確認した羽伏浦動画と公式の地点写真を参照しています。写真の未校正カメラ・潮位・撮影条件から絶対寸法や波高・周期を測定したとはしません。[参照記録](habushi-reference-v6.md)、[公式・堀切](https://niijima-info.jp/spot/2225/)

ImageGenで1254×1254の軽石diffuse画像を生成し、実寸として作者が指定した2mのworld-space triplanar投影へ接続。画像は現地写真・PBR計測ではなく、微細な照明が焼き付いている可能性があります。元Google画像の画素は公開素材へ含めていません。読み込み状態をready/failedで診断し、失敗時は従来素材へフォールバックします。生成toolがモデル名を返さなかったのでモデルidentityは断定しません。[素材の根拠](../src/assets/niijima/provenance-v9.json)

volume=1の候補は67本の不揃いの溝、疎らな硬い層、適応断面595、132,090三角形。独立レビューでは、縦幕状の広い面、規則的な細帯、均一な崖裾が実写真と異なり、通常表示への昇格は却下。逆向きの帆状の地形は実際の描画三角形をpickし、追加volume外の既存2m地形面をx5906.742/y18.902/z-1162.283で確認しました。これは地形の存在や測量値の誤りの証明ではなく、表示形状の原因切分けです。元データを都合よく削って一致と主張しません。

## 水中の実深度と反射

同じ潜水地点でraw landDepth/waterDepth/waterAlphaを一時Float targetへ読み出しました。中央列の画面Y270/290は約18/40m先の水面、Y310は水面も地面もhitなし、Y330/350は遠い地形、Y370以降は近い底です。通常描画への追加readbackはありません。

compositorの水中光路を平均海面y=0・85mで打ち切る処理を修正。波面の法線へ地球曲率を反映し、水面の裏からも現在の水中sceneを反射します。oblique projectionを明示的にinvertし、反射hitまでの第二光路にも吸収と散乱を加えました。v8の固定した暗い天井は、実画面で波状の反射へ改善しています。遠方の水平帯は残り、完全修正とはしません。

反射は平面Reflector＋波面法線によるUV変形で、取得hitと散乱方向が常に一致する厳密な波面raytraceではありません。海底・生物配置・手の肌・Snell窓の歪みも写真品質に未達です。独立レビューで限定改善として保持可能、新規の具体的P1は未発見と判断されました。

## 実行して見つけた船の不一致

泊の水際から通常controller入力で約75秒移動し、walkからswimへ移って描画された船尾はしごへ到達。しかしx-116.7505/z-88.551の接近位置でE乗船が失敗しました。乗船判定が船の横だけを基準にし、見える船尾はしごと一致していなかったためです。

BOAT_ACCESSで描画・操作の船尾座標を共通化。はしご→足場→port通路→着席を5秒、逆を4.4秒で接続します。独立レビューで後部ベンチ、座面への立位侵入、横桟・後端、曲線支柱の交差を順に発見。後部ベンチを右へ寄せport椅子を減らして通路を確保し、着席時の膝・torso姿勢を連続化、canopyと全支持部を頭上・通路外へ移しました。実際のCatmullRom/TubeGeometry、ベンチ・椅子・桟・後端をswept solidsに含め、乗降が通る回帰検査を追加しています。seated torsoのproxyは全肢体の衝突を解くものではありません。

修正後は以前の失敗位置をQA再初期化し、実ブラウザーでclimb→walk→helm、操船加速、惰性減速、走行中の下船拒否、停止後のswimへの下船を確認しました。途中のE動作・操船中に位置を再設定していません。ただしコードreload前後をまたぐ一続きの岸→船の証明ではなく、native keyboard/Human PASSや全島間の航海も未確認です。
