# V31 — 新島の沿岸波を通常の旅へつなぐ（2026-10-07）

波の実装: `d6bd1c2f4f02a32ffd59f80f4ef54199c084b3f4`、気泡の多様化: `d3d3bed02233b2027a2c64e3d9f29045d7e0c4e3`。基準: V30 `be514ddc57712445204e1623205c46c51a34cf28`。

通常起動でも、羽伏浦・シークレットなど新島の沿岸に近づくと、水深に沿う波の計算が動く。新しい場面や移動モードを選ぶ必要はない。泊・沖合では従来の波へ戻り、同じ一人称の世界を移動する。候補だった体積白水、波が巻く追加形状、別の岩配置は、一括で有効にしていない。

## 波が消える二つの原因

従来の沿岸候補は、羽伏浦で動かすと波が極端に平らになった。まず摩擦・外力・境界を除いた周期波で、計算そのものの減衰を調べた。1.5m格子、水深4m、波長24m、振幅0.025mで96m分進めると、倍精度の旧方式は振幅を約1%しか残さなかった。

自由水面と流速をセル内で再構成するMUSCLと、2段のSSP-RK2を加えた。乾いたセルの勾配を抑えて静水時の偽の運動量を修正し、2軸の計算に合わせて時間刻みも保守的にした。計算前の状態・予測・修正を別の3枚に保存し、同じ描画先を読み書きしない。泡・摩擦・境界処理は物理時間ごとに1回行う。

さらに実GPUで、同じ輸送shaderを周期的な平底の試験へ使った。16ビットの状態保存では、小さい水深更新の反復によって水量まで大きく失われていた。32ビットに替えると、この試験の水量誤差が小さくなった。

|---|---:|---:|
| 一次・16ビット、軸方向 | 5.69% | −19,952 |
| 一次・32ビット、軸方向 | 0.96% | +0.0244 |
| 高次・16ビット、軸方向 | 1.64% | −36,742 |
| 高次・32ビット、軸方向 | 58.14% | +0.0605 |

| 高次・32ビット、斜め | 76.22% | −0.0123 |

初期のセル水深総和は約65,536。一定のセル面積2.25m²を掛けると体積になり、kgではない。波の指標は水深と流量の基本波成分を合わせたもの。斜めの波長は周期境界へ合わせた約22.63m。全ケースでGLエラー・非有限値は0だった。これはこの実行環境での閉じた輸送試験であり、現地の波や全GPUを保証する測定ではない。

通常の沿岸状態もRGBA32Fへ変更した。平底の滑らかな波について高次化を確認しており、海底は区分一定のまま。砕けた波の空気巻き込みや3Dの乱流まで解いているとは扱わない。数値手法の背景は[Audusseらのhydrostatic reconstruction](https://epubs.siam.org/doi/10.1137/S1064827503431090)を参照。今回の実装・検証は本リポジトリの独自の組合せである。

## 泡の見た目

同じ波の状態で、白水の粒子層と水面の泡を順に隠して比較した。広い白い塗装に見える主因は水面の泡だった。数cmの気泡の穴・縁の陰影と中間スケールの変化を加え、画素が覆う範囲に合わせて細部をならす。泡の縁を半径単位で計算する部分のフィルター幅も同じ単位へ合わせた。

独立レビューは白い塗装の印象が弱まった限定改善と判定し、広い白膜や模様に見える輪郭は残ると指摘した。rootは通常の風の羽伏浦・シークレット、移動中の画像、保存した実録画の再生とフレームを確認した。泡の形は作者による手続き的な表現で、実写素材や現地測量ではない。

録画では均等な点模様も見つかったため、気泡の径に大きな偏りを持たせ、配置を変形し、縁の光を太陽の方向に合わせた。大きさに応じてフィルターも変える。比較と数値の保存先は[実行記録](checks/v31/runtime.json)。
