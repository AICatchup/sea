# V70 — 開いたスキャン岩の接地と遠景の輪郭

2026-10-13。Chrome の実際の WebGL 描画で、浜・水際・岩の近距離・俯瞰・水中を確認した。実写同等、全箇所の改善、実測センチ精度は未達成。

## 通常版への採用

既存の棚状スキャン岩は、元データの端が開いた地表の一部である。V69 の「一部の頂点が地面に埋まる」条件だけでは、端が板状に突き出す配置を見逃していた。今回は元の実頂点から切断境界を求め、世界座標で辺を最大10cm間隔に分割し、全サンプルを3.5cm以上地面へ埋める。最大1.5mまで法線方向に移動しても収まらない配置は採用しない。形状・UV・写真材質を伸縮して埋め合わせない。

通常地形では棚岩60個を検査し、18個を追加で最大1.15m沈め、3個の不成立な配置を除外した。既存の乱数列を消費し終えてから判定するため、他の岩と水中の岩礁の乱数列を変えない。描画と衝突は同じ行列を使う。ロード時だけの計算であり、追加テクスチャや毎フレームの接地判定はない。`shelfrim=0` で V69 の接地条件と比較できる。

遠景の軽量化にも接地条件を引き継いだ。従来はスキャン2種の4段階で切断境界が変わり、埋めた端と異なる直線が現れる可能性があった。棚岩だけ meshoptimizer の `LockBorder` を使用し、境界を崩す sloppy fallback を禁止した。軽量化後に位置を溶接した境界の完全一致を検査し、不一致なら元の index を保持する。実データでは143辺／108辺が全段階で保持され、三角形数の差は各段階で最大1枚だった。別アセットで元の index に戻る場合は軽量化の目標を超える可能性がある。

同じカメラ・時刻の比較では、砂浜から突き出す板状の岩と、崖際の浮いた切断面が解消した。俯瞰でも目立つ退行は見つからなかった。独立した補足レビューはこの限定した通常版への採用を支持している。10cmサンプリングは任意の地形に対する連続接触の数学的保証ではない。

## 実測地形の比較候補

既存の `tomarisurvey=1` では、旧地形の低い砂浜が実測で高さ4m前後の岩棚へ置き換わっても、砂の材質が残っていた。旧地形と実測後の高さの差から露出岩の重みを推定し、砂／岩の色・法線・粗さ・遮蔽を同じ重みで切り替える。地形、床、海は変更しない。`surveyrock=0` で比較できる。

これは作者による基盤材質の推定であり、LASの地質分類ではない。649386頂点のうち35958頂点に重みが付き、属性約2.60MBを実測候補だけに追加する。ソースで確認した乾いた岩棚、実際に描画する境界の連続性、砂浜の保持、共有テクスチャの所有権を検証した。実測地形全体は崖の縦方向の引き伸ばしと大きな丸い面が残るため、通常版に昇格していない。

## 検証と残る差

最終チェックの結果と実測値は `checks/v70/verification.json`。保存画像はゲームの実描画であり、通常移動の成功証拠とは区別する。内部へ入った診断カメラは受入画像から除外した。

崖の大きな平面と丸み、砂が急斜面へ盛り上がる形、樹冠の隙間、近距離の幹・葉・地面との接続には、実景と明確な差が残る。大きな地形の置き換えには、可視面・床・衝突の一致と、浜に立つ複数方向からの比較が必要である。今回の局所的な接地修正を、海岸全体の再現完了に読み替えない。
