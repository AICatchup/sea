# V8 current-FFT crest shell candidate

The V7 screenshot `work/tomari-v7-qa/secret-seaward-foam.png` shows shallow texture and whitewater but no resolved transparent curl. The surf video observations are recorded in [habushi-reference-v6.md](habushi-reference-v6.md); the parent additionally observed RKgTU7eZyWw at 4:34–4:35. H and T have not been measured. This candidate has not been visually approved or GPU rendered in its worktree.

`ShoreBreaker` adds one 96 m square mesh, 96 subdivisions (1 m sampling), 18,432 triangles, no allocations per update, no additional texture or GPU readback. GPU sampling cost is appreciable: three inverse-chop iterations for each of three height evaluations, plus terrain and dissipation. A one-draw budget does not establish a frame-time budget.

Current long and short FFT displacement (384 m / 24 m repeats) supplies every height and slope. Three inverse-chop iterations and the existing `shoreWaveScale` agree with whitewater. Actual bathymetry RG uses the half-texel convention. Positive height, current depth-cap dissipation, descending shoreward slope and negative crest curvature must all be present. An uphill terrain gradient supplies incident direction; there is no time uniform, fabricated periodic swell, cached birth state or drifting camera-attached crest. The mesh origin follows the camera continuously, while all sampling stays in world coordinates. Sampling lattice movement can still cause sub-meter tessellation shimmer.

The visible shell is only on exposed 0.2–3.8 m wet cells. Deep water, land, negative/trough heights and nonbreaking energy are hidden. Land depth is sampled in the fragment shader using the renderer's existing occluding depth. Add the group to waterScene, never to the land depth scene. Underwater hides it.

The shoulder fold uses instantaneous FFT slope as phase and radius `min(.65, depth*.24)*gate`. This is an artist approximation of a thick forward crest shoulder. It cannot solve finite-depth dispersion, conservatively propagate energy, establish an actual plunging lip, enclosed hollow barrel, splash impulse or collapse history. The underlying FFT still has its original dispersion. Neighboring sampled points can fold into a shoulder, but a full connected overhang is not guaranteed. Transparent color/Fresnel is approximate and does not sample the full renderer refraction/sky. It must be treated as a candidate requiring actual shoreline screenshots and frame-time checks, not a photoreal or physically correct surf result.

Integration: instantiate once, call `bindUniforms` with the same shared water IUniform bag (including long/short FFT, bathymetry/bounds/resolution, swell/wind/choppiness, viewport and land-depth texture/readiness), add `group` to `waterScene`. Each frame after FFT/depth uniform updates call `update(camera.position.x,camera.position.z,underwater)`. Dispose on owner teardown. `bindUniforms` binds object identity, so ordinary renderer value updates remain authoritative. CPU tests verify gates and lifecycle only; they cannot validate GLSL compilation or surf appearance.
`breaker=1` remains query-only after root GPU compilation and frozen on/off screenshots. The current sampling includes uBathyTriangulated with the other shared uniforms. Independent review observed subtle cyan details but no clear useful full curl/barrel; default promotion was rejected. See [current acceptance](verification-v8.md).
