# V41 — 元の25cm実測格子で白ママ断崖と浜をつなぐ

東京都の実測地形09QC1711を、シークレット付近の約400×300mへ組み込んだ。旧い数メートル単位の標高を滑らかにした面から、細かな柱・棚・崖脚・浜の高さがある形へ変わる。現在は1区画で、周辺を含む海岸全域の実測置換は未完了。

## 形状・精度・出典

東京都配布の0.25m GeoTIFFの192万標本を保持し、130個の描画区画へ分けた。全距離で元の頂点を保持する高さ場で、カメラから外れた区画だけ描画対象から外す。三角形は3,834,402枚。区画の境界では位置・法線を一致させ、同じ三角形を歩行の床にも使う。

0.5mへ一律に間引いた試作は、急な崖で元データに対して最大約7.4mの高さ損失が出たため採用していない。現在の元標本位置の数値変換とcm整数格納の誤差は、全192万点で最大約6.1mm。**この値は現地との1cm一致ではない。** 座標変換の公称精度は1mで、測量自体・撮影時期・現在の浜との一致は別の不確実性がある。外周12〜32mの接続帯は既存地形へ補間する。

[東京都の配布ページ](https://www.geospatial.jp/ckan/dataset/tokyopc-shima-2023)、CC BY4.0。[元データ・再現方法・精度の境界](niijima-native-survey.md)。元のZIPとTIFF、派生データをハッシュで結び、元GeoTIFFからの再生成を照合済み。LAS点色は材質として貼っていない。

## 水際の不具合修正

地形が細かくなった結果、浅水計算の範囲に対して水深テクスチャの余白が足りず、水が崖の上へ飛び出す三角形になった。水深タイルを切り替える境界でも浅水計算の全範囲を覆い、地形情報が変わると古い水深を流用せず同じ自由水面から再初期化する。

また、干出したセルへ通常のFFT波の高さを戻す処理が孤立した小さな水の尖りを作っていた。干出した場所では海底を露出させ、濡れている遡上波と沖のうねりは維持する。砂と白い岩の分類も三角形ごとに切り替わらない連続した法線へ修正した。

## 実行・画像・回帰確認

- 374テスト、型検査、Viteと単体HTMLのビルドが通過。
- 独立幾何チェックは切り抜き三角形の7,928点で高さ欠落0、外周・区画境界114点で表示される床との最大差約0.093mm。測量精度の検査ではない。
- 内蔵ブラウザで浜を開始地点に、波を動かしたまま歩行→泳ぎ→潜水→浮上→上陸を連続実行。541サンプル、最後の接地を確認。QAは実controller入力を使い、OSの物理キー長押しとは区別する。
- 風12・swell1.25の強い海況設定で12秒間の連続変化を確認。浅水計算12.03秒、時間取り落とし0、泡と飛沫の新しい発生あり。この設定は現地の通常波高の観測ではない。
- 5視点と強い波の4時点を独立目視。巨大な水の板・尖塔、細い水のblade、白い三角面は解消し、限定改善として採用可。
- 単体HTMLを静的HTTPで実行し、実測地形が標準で有効、開発用QAなし、外部素材取得0、console error0を確認。file://起動は未確認。

**残差:** 薄い水膜の角、実測区画と周囲の形の密度差、別地点スキャン由来の灰色材質、平らな大きい泡模様。崖の侵食・漂砂による動的な地形変化は未実装。[砂浜の形成と強い波の調査・残作業](habushi-coastal-processes.md)に記録した。全体の実写品質・全海岸の1cm一致・最終紹介動画は未達のため、ゴールは継続中。
