# V68 — Chromeでの実描画比較と低木LOD

2026-10-13。ユーザーのChrome使用承認を受け、実際のWebGL描画を確認した。全体の写実性は未達成。

## 採用

低木の詳細度を距離だけでなく投影サイズでも選択する。40px以上を近景、8px以上を中景の候補とし、中景枠を180から1200へ拡大した。既存の135万triangle上限、配置、当たり判定、9 drawは維持。通常の海岸とcrown-support再構築に同じ設定を適用。`?shrubdetail=0`で旧配分を比較できる。テクスチャの追加なし。ただし描画triangle数は増えるので、無料の性能改善とは扱わない。

1280×720/high/day、波の時刻を固定し、spawn・cliff・shoreの各カメラを一致させてA/Bを保存した。Solによる全6画像の独立レビューでは、右岸上端の低木の輪郭が少し厚く連続し、3視点で明確な退行なし。改善は植生の細部に限定される。

## 実行確認

- Chrome / Radeon RX 7600 XT / ANGLE D3D11。前面表示、high、1280×720でA/B各120 rAF間隔の平均は双方16.67ms。波を固定した限定的な比較。
- 採用設定でUIから波を再生。6.008秒に361フレーム、波時刻も6.017秒進み、診断60fps。歩行・船上・全機器の性能保証ではない。
- 初期の約1fpsは前面化前の観測。`Page.bringToFront`後にrAFが16.7msへ戻ったため、その数字をGPU性能や変更の退行根拠に使わない。
- 全558テスト成功、型検査と本番ビルド・単体HTML生成成功。従来の大きなchunkとmocap-gaitのdynamic import警告は残る。

画像と実測は [checks/v68](checks/v68) に保存。QAの固定カメラは通常の移動成功の証拠ではない。

## 採用しなかった案と残件

- 泊の砂判定を低い面へ絞る試行は、白い壁の解消を裏付けられず撤回。原因を砂だけと断定した初期仮説も撤回。
- V67 `rockvariation=1` は新島北向きの同一カメラで実描画できた。亀裂模様は変わるが、巨大な平滑面と単調な陰影が残り、独立レビューでも明確な全体改善を認めなかった。既定OFFを維持。
- 崖の丸い大形状、砂との単調な接触帯、斜面上の葉の地中支持、LOD切替時の連続性が残る。実景と同じ形状・実写同等・全グラフィックス完成とは宣言しない。
- 公式写真は前段V67の参照に留め、新規の写真素材や計測値として流用していない。
