# 波音と操作表示の改善 — 2026-10-23

## 波の取得周期と音の整合

GPUの水面高は約0.2秒間隔で取得する。一方で音の状態はUI更新ごとに計算するため、古い値が続いた後の水面高の変化を短いUI間隔で割ると、波の上昇速度が過大になっていた。

水面高の取得時刻を音へ渡し、新しい取得値の間隔で上昇速度を求める。次の取得までその速度を保持し、既存の短い立ち上がり・長い減衰で音量を滑らかにする。取得の中断・巻き戻し・再取得・一時停止復帰を、新たな波の衝撃として扱わない。音の前回状態はwaveもコピーし、呼び出し側のオブジェクト再利用で過去値が変わらないようにした。

これは音量制御の改善であり、波の3D形状を新たに修正した報告ではない。

## 無駄な更新と起動案内

- 非表示のアクティビティHUDは内容を更新せず、表示中も変更のない文字・属性を書き直さない。
- UI更新も描画頻度と同じ予約方式を用い、高リフレッシュレートの画面で30Hzからずれにくくする。
- GPU起動失敗時の復旧手順を画面内に表示。一般のエラーをGPU不足と断定する見出しも修正。
- 高さ163pxの実ブラウザでも案内をスクロールでき、再試行ボタンへ到達できることを確認。以前の中央寄せでは内容が画面外へ切れていた。

## 今回の検証

- 音・フレーム予約・水面高取得・活動状態の関連28テスト成功。30/60/120Hzでの音量の一致、取得中断からの復帰、波が過ぎて6秒後に追加音量がピークの1%未満へ減衰することを含む。
- TypeScript検査、本番ビルド、単体HTML生成成功。
- Chromeの実DOMで、HUDを120回更新して変更のない書き込み0回、非表示時も0回。ラベル変更、操作禁止、表示復帰を確認。これはGPUなしのHUD部品検証で、ゲーム全体の通し操作ではない。
- Chromeは引き続きWebGL 2を作成できない。今回の実海面描画、耳による音の受入、新規動画、消費電力測定は未実施。

前版の全636テストの実行結果は[省電力版の記録](release-readiness.md)を参照。この追加変更に対する全テスト再実行は行わず、影響範囲を検証した。
