# 羽伏浦・白ママの浜と波を作る根拠

## 確認した資料と適用

- [地質調査所「新島地域の地質」(1987), pp.61–62](https://www.gsj.jp/data/50KGM/PDF/GSJ_MAP_G050_09001_1987_D.pdf): 崖下に崩落物が堆積し、火山砕屑物の侵食・波や流れの選別によって海浜が形成される。見た目では、露出した層・崖錐・浜・沖の堆積域をつなぐ。古い報告であり現在の全海岸形状を示す図として転用しない。
- [GSJ地質標本館・羽伏浦の白砂](https://www.gsj.jp/Muse/sand/J-14.html): 標本の主成分は約0.5mmの丸い石英粒で、少量の軽石片等が混じる。砂全体を粗い岩・均一な純白塗料として表現しない。これは一つの標本で、浜全域の粒度や色が同じという根拠ではない。
- [梅田ほか(2020)・羽伏浦の侵食調査と再現計算](https://doi.org/10.2208/kaigan.76.2_I_463): 高波浪による崖の後退に加え、その後の波の作用で砂が堆積しバームができた例を示す。短時間の寄せ引きと、荒天・季節を通した地形変化を区別する。論文の4m/6mは再現計算の条件で、毎日の羽伏浦の波高として使わない。石廊崎での極端波浪を羽伏浦の通常観測値へ置き換えない。
- [東京都の羽伏浦紹介](https://www.gotokyo.org/jp/spot/244/index.html)と[新島公式パンフレット](https://niijima-info.jp/cms24/wp-content/uploads/2025/01/A4.pdf): 長い白砂海岸と強い外洋の波が特徴。羽伏浦のビーチブレイクと南側シークレットのリーフブレイクを区別する。幅・波向・季節条件は場所ごとに異なる。
- [東京都公式映像 Tokyo Nature Drift](https://www.youtube.com/watch?v=Nwf2TvqiY5g): 新島の砂浜と崖の場面、72.27秒付近の羽伏浦の波打ち際、237秒付近の泊の入り江を内蔵ブラウザで確認した。新島の幅のある砕波帯、泡の後ろの青緑、浜の湿った帯を確認。全編・連続した波周期の計測は未実施で、紹介映像の編集音を現地環境音の記録として使わない。動画画素はゲーム素材へ転載していない。

## 実装へ反映した範囲

V41は東京都の元25cm地形標本を残し、実測の崖脚と浜へ水面を接触させる。細かな地形へ換えた結果、水深タイルの端が浅水計算の範囲に足りず、以前の水深を新しい崖に加算する不具合が表面化した。地形タイルに十分な余白を持たせ、床の契約が変われば水面から深さを初期化し直す。

水が引いて干出したセルは、海底を覆う通常波面へ戻さない。沖のFFT波、濡れている砕波・遡上の高さ、領域端の接続を保持して、乾いた場所だけを整合させる。砂の分類を三角面ごとに切り替えず、細かな計測三角形が白い岩片の模様にならないようにした。

風12m/s相当・swell1.25の12秒QAは設定上の強い海況であり、観測日の再現ではない。SWEの圧縮による泡・飛沫は近似で、空気を巻き込む砕波の3次元流体計算ではない。波打ち際の白い泡の厚み・粒・残留・流れには改善の余地がある。

## 残る完成条件

V43では沖のスペクトルと浅瀬の入射方向を接続し、通常の薄い泡にも符号付きの浅水流速を渡した。平らな浅瀬の入射流量と、同じ泡が引き波で沖へ運ばれる経路を検証した。厚い立体泡は実写より固体片に見えるため標準採用を保留している。[変更と検証範囲](verification-v43.md)。

V45では浅水計算の初期・境界入力にも、描画と同じ水深と遮蔽の波形を適用した。乾いた砂浜へ沖の波を直接作っていた挙動を除き、計算された流れによる遡上を保持する。同じ海況の20秒比較で、崖下の高い水膜が減り、波と泡の発生は残った。[統制GPU比較と実行範囲](verification-v45.md)。

- 日付の異なる実景に見られる浜幅・砂の堆積帯を整理し、測定時期の形と推定する季節変化を混同しない。
- V49では実際に水が届いた地面の光学的な濡れを記憶し、引いた後の水膜と湿りを別々に減衰させる。乾いたsolverセルの誤濡れと、斜面への履歴の拡大をGPUで修正した。乾燥時間は制作上の調整値で、砂の移動や侵食ではない。[変更と検証](verification-v49.md)。
- 風向・入射波向・浅瀬での屈折・砕波の連続を確認し、複数のうねりが寄せる時間変化を再現する。
- 泡が崩れ、浜を薄く覆い、引き波に乗って残る表現を実映像と比較する。
- 崖の侵食・崩落・漂砂による動的な地形変化は未実装。秒単位で巨大な崖を削る架空の速さを、現実の侵食再現としない。まず実測の地形と正しい水面接触を保ち、その上で保存・衝突・物体支持が同じ形を使う更新経路を作る。

全体の写実品質と「現地1cm一致」は未達。数値変換の細かさ、測量データの精度、現実の時点一致、ゲームの見た目は別に検証する。
