## 現在の採用状態

通常では `canopy` が有効。`canopy=0` は比較用。`ground=1`、`coastform=1`、`crown=1`、`leafvolume=1`、`originaltree=1` は候補で、通常は無効のまま。

地表候補は2.14mのCC0写真素材を使う。元のレビューでは、近景の黄土色と遠景の緑をカメラ距離で切り替える不整合を指摘された。`8f988af` では距離依存を除き、世界座標に固定した土・苔・落葉の混合へ修正した。修正後の多方向描画・現地の色との照合・動作時の評価はまだ必要。

岩壁候補は接続した表裏のスキンと斜交する割れ目を持つが、人工的な三角形／V字形状が目立ち、通常採用は拒否された。30本の非多様体エッジも見つかった。`8f988af` は角だけで接する領域を分離し、実形状にも小さな間隔を設けた。実際のスキンは5,852頂点・11,364三角形・1,065セルで、回帰テストでは全エッジが2面に接続する。**これは見た目のV字形状の解消、現地測量、実写再現の証拠ではない。**

高密度の元モデル植生候補は粗い距離帯の葉の寸法を拡大しており、画面上で過大な代替が残る。通常採用・植物学的正確さ・写真同等の主張をしない。

## 実行入口

Node.js 22.13以降または24系で、ロックファイルから依存を導入する。

```sh
pnpm install --frozen-lockfile
node --experimental-strip-types --test --test-concurrency=2 tests/*.test.ts
pnpm build
pnpm dev --host 127.0.0.1 --port 5187 --strictPort
```

大量の地形テストの同時実行でメモリ確保エラーが出たため、並列数2で検証する。WebGL2・浮動小数点描画が必要。ブラウザ／GPUがない場合、CPUやビルド結果を見た目・移動・GPUの成功へ昇格させない。

開発用 `?capture=1` では `window.__seaQA` と診断 `window.__sea` が使える。`captureTerrainPose` は1280×720を要求し、カメラ高さと時刻を固定できる。開始地点指定は検証用で、移動経路の証拠にはならない。別インスタンスの静止比較では水と魚の計算履歴が一致しない。
