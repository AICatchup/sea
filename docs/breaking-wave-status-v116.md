## 不自然さの原因と変更

1. **波頭より遅い放出。** 急な波面の速度を、別に動く放出元の波頭の速度として使っていた。実画面の4秒地点では、水が波頭を約0.2mしか追い越さず、約0.1秒で元の広い波面へ埋まる例があった。放出元の移動速度を追跡し、その座標系で余剰速度と鉛直速度を制限する。
2. **広い土台に巻き込みを載せるだけ。** 上向き速度だけを増やす案は、空中に透明な薄い屋根を作ったため棄却。強い砕波の前面を局所的に急にし、落下する水の下に空間を作る。最終版では最高24区間、波頭位置・高さ・落差・幅・寿命を共有し、描画・着水判定・プレイヤー付近の水位・集光の参照へ反映する。検出元の高さ場には戻さず、自己増幅を避ける。
3. **存在しない水への接続。** 着水済み・未生成の行を、空中の行へつないでいた。未生成の座標が現在の放出点を指すため、大きな三角形が空中を横切った。無効行は最寄りの生存端へ縮退させ、被覆はゼロのまま保つ。消えた列も隣の生存列へ縮退させる。
4. **着水した古い先端を使う。** 波全体の年齢を先端座標としていたため、最初の水が着水した後の落下端に泡が付かなかった。各列の生存区間から、現在の先端・厚み・泡を計算する。
5. **同じ波頭の重複。** 別の波面を検出しても、波頭へ戻ると同じ場所になる場合がある。放出点を求めた後にも所有範囲を確認する。生まれた直後や描画終了後の前面処理中も、所有権を失わせない。
6. **白い滝の模様。** 水平な泡の面積を、急になった前面全体へそのまま写していた。急な面ではその被覆を弱め、落下する水自身の泡と着水後の泡場へ分担する。

これらは通常のゲーム描画に適用する。撮影カメラのためだけに別の波や再生アニメーションを挿入しない。

## 検証の条件

開発用UI: `/?capture=1&view=secret-north&waverecord=1`。比較時刻と目線高を選べる。18秒を最大1/60秒の計算刻みで進め、24fps・433枚の実描画を保存する。動画への中間フレーム生成はない。音声は同じゲームの音声グラフから48kHzステレオで生成し、シミュレーション時刻へ合わせる。実時間FPSの測定ではない。

CPU断面テストは、高さ2m・幅8m・速度7m/sの広い移動波に対し、前方への放出、空洞の持続、着水、後続の水の受け渡し、最終消失を確認する。無効な行が空間を橋渡ししないこと、重複検出、静かな波を持ち上げないことも回帰対象にした。数値結果だけでは視覚合格としない。

## 最終スナップショットと受入結果

上向きの押し上げで透明な屋根を作る案は採用せず、最終版の放出の上向き速度はゼロ。前方へ出た水の落下を重力で計算する。局所前面は最大24区間、実際の波頭に沿う3区間ずつで再構成する。これは物理モデルの置換ではなく、なお体積を保証しない試作である。

GPUの19テクスチャ単位に関する警告を確認し、波の座標・端・形状を一つのアトラスにまとめた。修正後のChromeでは同警告の再発を確認していない。これは光学・物理の合格ではない。

最終版の全681テストと型検査、製品ビルド、単独HTML生成は成功。最終版そのものを18秒・433フレームで保存した。過程の別係数の動画を最終版の証拠には使わない。4秒地点には滝状の白さや硬い面が残る。巻き込みの意図が見えても、実際の水とは運動が乖離しているという指摘を未解決として採用した。

## 物理モデルの限界

前面の補間は高さ場と空中の水をつなぐための局所的な形状再構成で、取り除いた高さ場の体積と放出体積を厳密に対応させていない。空気の圧力、3D渦、表面張力も解いていない。基礎となる沿岸の流れと、上に重ねる巻き込みの近似を区別する。大きな樽状の空洞や白水の厚さを実写同等に再現したという宣言はしない。
