# 地形データの展開負荷を削減 — 2026-10-23

新島・泊海水浴場・各島の標高データを、共通の16bitデコーダーへ移行した。対応ブラウザでは `Uint8Array.fromBase64` のバッファーをそのまま使い、従来ブラウザでも文字列から `Int16Array` へ直接書く。大規模な文字列イテレーターと汎用配列への中間展開、および不要な全データコピーを避ける。

符号、欠測値 `-32768`、リトルエンディアン、各サンプル値を保持。毎回独立したバッファーを返すので、新島の海岸補正が元データやほかの地形へ漏れない。地形の形状・解像度、素材、波、描画設定は変更していない。JavaScriptの配信サイズを削減する変更ではない。

人物・モーションの外部素材は、既存実装ですでに選択時だけ取得していることも確認した。

## 単体測定

Node.js 24.22.1で新島の384万サンプルを展開し、従来版と改修版をそれぞれ独立プロセスで1回測定。対象は標高のデコードから高さ・有効値配列の作成まで。GCを測定前に実行。数字は単一環境の参考値で、ブラウザ全体の起動時間・FPS・消費電力を示さない。

| 指標 | 従来 | 改修後 |
| --- | ---: | ---: |
| 展開時間 | 636.6 ms | 35.6 ms |
| 処理直後のRSS増加 | 297.0 MB | 19.0 MB |
| プロセスのピークRSS | 483,168 KiB | 210,276 KiB |

このNode版はネイティブBase64 APIを持たず、互換処理の測定。両方の高さ・有効値配列のSHA-256は `95dbbafc45f977ab2968cd422822ce1dd391a884aeaab48bd4777cdee591185d` で一致した。測定順・GC・JITによる変動はある。

再現コマンド（同時に走らせない）:

```sh
node --experimental-strip-types --expose-gc scripts/benchmark-elevation.mjs legacy
node --experimental-strip-types --expose-gc scripts/benchmark-elevation.mjs current
```

## 検証

- デコーダー3テスト: 格納済み全標高データと独立したlittle-endian読取りとの全サンプル一致、符号端点・欠測値、長さの検査、独立した所有権、直接バッファー再利用。
- 既存26テスト: 新島の実測登録・泊の実測地形、海岸の境界・足元と描画用三角形の一致、衝突・航路、海岸補正。並列実行なしで成功。
- 実際のChromeでネイティブAPIを使用し、新島384万点の同一ハッシュを確認。デコード単体は1回の測定で5.9 ms。Nodeの測定とは範囲と実行環境が異なるので直接比較しない。
- TypeScript検査・本番ビルド・単体HTML生成を実施。大きなチャンクと既存の動的importの警告は残る。

ChromeのSEA本体は引き続きGPU非対応画面。実際の海の描画、ゲーム全体のメモリ・FPS、実消費電力、新しい音付きMP4は未確認。今回のデータ一致を見た目やゲーム完成の受入へ置き換えない。[残る完成条件](release-readiness.md)
