# V29 — 水平線の黒い斑点を抑える（2026-10-07）

実装: `a8ab50fffe119e95599d80e20dc1c5ff0f9ed626`。基準: V27 `90d15136345e241b259e1fc723c8f71f036958a0`。

羽伏浦のメインゲートから見える遠い海に、細かい黒い斑点が並んでいた。実GPUの同じ8画素を読み、1画素が覆う水面が46〜893mあるのに、波の傾きを求める差分幅は14mに制限されていると確認した。隣接画素の空反射の重みが0〜1へ大きく変わり、未解像の細かい傾きが暗い波間の反射へ切り替わっていた。

描画用の長波傾きは、遠方でも画素の大きさに従って差分幅を広げる。近景の21.54m以下のfootprintでは従来と同じ計算になる。FFTの波、頂点、波高、泳ぎ・船の物理、地形、衝突は変更していない。追加のtexture fetchもない。通常有効で、`?wavefilter=0`から従来表示を比較できる。

同一カメラ・時刻34.016666666666666・昼・高品質・1280×720でoff/on/offを比較した。水平線の黒斑はonで消え、offへ戻すと再現した。8画素のoffの数値も完全に一致。門の右の固定した海面矩形では、RGB平均90未満の画素は1.94%→0%→1.94%となった。この小領域の描画指標であり、実写品質の評点ではない。

独立したコード・画像レビューで、この遠方の修正に阻害事項は見つからず限定採用可能と判定。rootは浅瀬、高所、海底、シークレット、水中から見上げる界面を追加比較した。水中の屈折・全反射も同じ法線を使うが、確認した界面に大きな回帰は見られなかった。

307テスト、型検査、本番ビルド、素材埋込HTML生成が成功。実行記録と画像は[checks/v29/runtime.json](checks/v29/runtime.json)。大きいbundleの警告と、既知のsky関数に関するドライバー警告は別途継続記録する。
