# Scanned fractured cliff material

The separately generated `tomari-west-volume-v32.glb` is a closed, inferred cliff relief using five bundled CC0 scan geometries and pinned samples of the existing DEM. `tomari-west-volume-v32.json` records hashes, provenance and the reproducible builder. It is not a Tomari photogrammetry survey. Its grey GLB material is replaced by this folder's world-projected PBR in the runtime; no source photograph pixels are baked into the geometry asset.

This folder contains the unchanged official **Rock Face 03** texture originals by **Dario Barresi** (photography) and **Rico Cilliers** (processing), from [Poly Haven](https://polyhaven.com/a/rock_face_03), under [CC0-1.0](https://creativecommons.org/publicdomain/zero/1.0/). [Poly Haven's asset license](https://polyhaven.com/license) permits redistribution of the asset files. No Google photograph pixels or derived Google texture are included.

The material is a generic weathered cliff reference. It is **not a Tomari scan**, and the source metadata does not establish rhyolite geology. Its angular, chipped and finely cracked structure was selected against Tomari's pale coastal crags. The shader reduces the source's brown mineral color and calibrates its dry palette toward gray-beige in linear light. This is an authored appearance adjustment, not a measured reflectance or geological match. Original image bytes are never recolored, recompressed or resized.

`manifest.json` binds the official info/files API endpoints, download URLs, author names, physical dimensions, API MD5, local SHA-256, JPEG frame dimensions and byte sizes. The four texture files total **33,194,776 bytes**, below the **35,000,000-byte** import limit:

- `rock_face_03_diff_4k.jpg`: 4096 x 4096 photographic albedo, loaded as sRGB.
- `rock_face_03_nor_gl_4k.jpg`: 4096 x 4096 OpenGL +Y tangent normal, loaded as linear data. The decoder normalizes the JPEG vectors before rotating or blending them.
- `rock_face_03_arm_1k.jpg`: 1024 x 1024 linear data; ambient occlusion in R, roughness in G, metalness in B. Runtime metalness is explicitly **0**. JPEG chroma bleed produces a small nonzero B channel; it is not sampled as a metalness map.
- `rock_face_03_disp_2k.jpg`: 2048 x 2048 grayscale relative height, loaded as linear data. Used to identify water-retaining depressions together with AO, rather than infer height from albedo.

The [official metadata](https://api.polyhaven.com/info/rock_face_03) reports a **2700 x 2700 mm** area. A source tile spans **2.7 world meters** on each projection. The 4K albedo and normals provide approximately **0.66mm per texel** for close rock inspection; AO/roughness remain at 1K because their variations are larger than fine normal detail. Relative height uses 2K for water-retaining depressions. The maps share the same physical UV coordinates despite their different resolutions. No geometric displacement is applied to the collision surface.

The shader uses signed world triplanar projection and three-cell stochastic triangular blending. All maps share each cell's offset and rotation. Normal XY vectors are inverse-rotated with the UV rotation, then converted through each projection's derivative cotangent frame into view space before the triplanar blend. Projection weights use the geometric world normal. UV gradients are computed before sampling branches and supplied to `textureGrad`, preventing hash-cell transitions or branch derivatives from selecting unstable mips. The coordinate field is independent of camera motion. Repeat wrapping, trilinear mipmaps and anisotropy are enabled.

Dry rock, wet rock, dry sand and wet sand use distinct roughness ranges. Rock wetness follows mean water height and an authored 0.65m splash reach, with greater retention in AO/height depressions. Sand has its own capillary transition and uses the unchanged **Sand 02** grain maps at **2.14m per tile**. These controls describe a persistent damp shore; they are not a simulation of measured wave contact. The integration owner can update `material.userData.coastWetness.waterLevel.value` and `.splashHeight.value` when the water state changes. Sky, lighting, exposure, and directional shadows remain renderer inputs; no sky color is baked into the rock palette.

`makeTerrainMaterial(grain, atlas, sand)` retains its existing factory signature. The new material owns only the four rock textures and disposes them once when the material is disposed. It exposes `material.userData.ready: Promise<void>` for the terrain owner's startup readiness; the caller retains ownership of sand, grain and the existing atlas. `?material=legacy` restores the previous material for development comparison. There is no normal user-facing material selector.

To reproduce this bounded import, run `node scripts/fetch-coast.mjs`. It uses the official API with a unique application User-Agent and rejects changed URLs, hashes, byte sizes or physical dimensions. Existing local bytes are preserved and verified. `node scripts/fetch-coast.mjs --verify` verifies all four originals without network access. [API terms](https://github.com/Poly-Haven/Public-API/blob/master/ToS.md) govern API service access separately from the CC0 asset license. The runtime bundles local images and makes no live API calls.

Local validation: the import headers and all API/local hashes passed; CPU image decoding confirmed nonflat AO, roughness, height and +Z OpenGL normals. Original JPEG normal lengths have p01/p50/p99 **0.8407 / 0.9860 / 1.0860**, so every sampled vector is normalized in the shader. More than **99.9999%** point into the tangent +Z hemisphere. Source ARM B averages **0.00476**, reinforcing explicit nonmetal treatment. Authored dry-rock reflectance across channels has p01/p50/p99 **0.1454 / 0.3339 / 0.7573** and a maximum clamp of 0.86. Factory readiness, disposal ownership, signed projection handedness, UV/normal rotation invariance, shader insertion anchors, legacy routing, type checking, production/standalone build and the existing 29 CPU tests passed. **WebGL compilation, texture upload, cross-view appearance and GPU frame time require integration-owner verification; these CPU checks do not establish a photographic match.**
